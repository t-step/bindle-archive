# Privacy boundaries

What counts as private for this repo, where private content is allowed to
live, and the guardrails that keep it out of Git. The stance is simple:
**committed files are publishable; everything personal lives outside project
repos by default.**

## What counts as private / personal data here

Never commit, to this repo or any project repo:

- secrets: credentials, tokens, API keys, private keys (Gitleaks + pre-commit
  cover the classic shapes);
- personal emails — especially Apple private-relay addresses
  (`…@privaterelay.appleid.com`), which uniquely identify an account;
- local machine paths (`/Users/<name>/…`) — they leak your username and layout
  and break for everyone else anyway;
- personal vault/notes locations (Obsidian vaults, iCloud paths);
- pasted chat/session transcripts (Claude, ChatGPT, etc.) — they routinely
  embed all of the above plus half-formed private context;
- medical, salary, recruiter, HR, or other personal-life details;
- personal denylist terms — names/projects/identifiers you've listed in
  `~/.claude-kit/private-denylist.txt` (one per line; read by the scanner,
  never committed).

"Private" is broader than "secret": a path or email that merely *identifies
you* doesn't belong in a shareable repo even though it unlocks nothing.

## Why session memory writes outside project repos

Session notes are where private context concentrates: what you were really
trying to do, what failed, pasted errors with local paths, half-decisions. If
those live inside a project repo, one `git add -A` publishes them. So the
session workflow (see the `session-continuity` skill) defaults all durable
notes to `~/.claude-kit/projects/<project>/` — a user-level directory that no
project's Git can ever see. Pointing `CLAUDE_KIT_NOTES_DIR` at an Obsidian
vault keeps the same property: the vault is not a project repo.

The `.gitignore` here additionally ignores the conventional local/private
patterns (`.claude-private/`, `*.private.md`, `session-notes/`, `.env`, …) so
that even a note accidentally created inside a repo stays out of Git — but the
ignore list is a seatbelt, not the design. Write notes outside the repo.

## Sanitized handoffs

A handoff generated by `/handoff` is meant to be pasted into a future session,
and sometimes into a committed doc or PR description. Before a handoff (or any
note) is committed anywhere:

- replace absolute local paths with repo-relative ones;
- strip names, emails, and anything from your denylist;
- summarize transcripts instead of pasting them;
- keep decisions and state, drop the personal narrative;
- run `bin/check-private-info.sh <file>` — it scans exactly these categories.

The commands themselves remind you: session notes are private by default, and
promotion to a committed artifact is an explicit, reviewed step (see
`docs/iterative-improvement.md`).

## Handling an accidental leak

If private info lands in a commit:

1. **Not pushed yet:** fix the file, `git commit --amend` (or interactive-free
   `git reset --soft` and recommit). Done — nothing left history.
2. **Pushed:** assume it's public. Rotate any secret immediately (rewriting
   history does not un-leak a token). Then rewrite history if it's worth it
   (`git filter-repo` on the offending path/string, force-push after
   coordinating — note this repo's own rule is that *you* push, agents don't)
   and contact the host to purge cached views if the content warrants it.
3. Either way: add the pattern that leaked to `bin/check-private-info.sh`'s
   patterns or your denylist so it can't recur silently.

## The guardrail layers

| Layer | What it catches | When it runs |
|---|---|---|
| `bin/check-private-info.sh` | personal patterns above + your denylist | pre-commit hook, `make check`, or by hand on any file |
| `.gitignore` | private/local note files ever becoming trackable | always |
| pre-commit `detect-private-key` | key material | every commit |
| Gitleaks (`.gitleaks.toml`) | secrets + the same personal rules, over history too | on demand / CI if you add it |

Run Gitleaks manually when you want a history-wide sweep:

```bash
brew install gitleaks
gitleaks detect --source . --redact
```

Pre-commit remains optional for basic use of the repo, but `bin/install-hooks.sh`
enables everything above in one step. The scanner needs no network access and
is plain grep — read it, edit it, add your own patterns.
